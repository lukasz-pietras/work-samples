At work

I'm the only support engineer at Shelf, an enterprise AI company. Instead of doing every investigation by hand, I built an agent that my colleagues and I talk to in Slack.

  1. Mention or DM in Slack
  2. Coordinator agent
  3. Helper agents for bigger jobs
  4. Looks at Jira, GitHub, CI, AWS, Datadog
  5. Answer or draft
  6. A person approves and sends
Where it livesA dedicated cloud server. A Slack app passes it mentions and DMs from me and approved colleagues.
Who does the workA coordinator agent on Claude, with Codex as a backup. For bigger jobs it spins up helper agents.
What it can seeJira, GitHub, CI, AWS and Datadog, at engineer level. Read-only by default.
What it asks me firstProduction data changes, merges, releases, deploys, deletes and access changes.
What it never doesPost anything a customer can see. Customer replies are drafts, and a person sends them.
What we use it forTroubleshooting, feature-request triage, documentation and log auditing. Plus scripts and MCP connectors for content exports, document uploads and bulk metadata updates.

Outside work: lunae.pl

lunæ is my partner's lingerie brand. She created it, designs everything and runs the brand. I do the technical side: the shop, the server and the automation.

I built it with Claude Code and Codex agents. They wrote most of the code. I wrote the briefs, made the calls and signed off on everything that went live. Build plus migration took 10 days.

Building the shop

I started from an empty server and WooCommerce in Docker.

ThemeWritten from scratch. No parent theme, no page builder. 91 files, about 7,600 lines.
PaymentsPrzelewy24. BLIK right in the checkout, cards and wallets on the provider's page. Tested with a real 1 zł order.
ShippingApaczka with three carriers, a pickup-point picker in the checkout, and labels that get the order number filled in for me.
InvoicesVAT invoices with my own PDF template, a company-invoice option at checkout, and company invoices sent automatically to KSeF, Poland's e-invoicing system.
E-mailOrder mails from the shop's own domain with SPF, DKIM and DMARC. The newsletter runs on self-hosted listmonk with double opt-in.
TrackingMy own cookie banner. GA4 and Meta Pixel only load after consent, and a test script makes sure it stays that way.

Moving the live shop over

The brand was already selling on Shoper, a hosted platform. So the next job was moving everything across without losing orders, stock or Google rankings.

Getting the data outA script pulls about 40 kinds of records from Shoper's API without tripping the rate limit.
Cleaning it upThe export was messy: guest checkouts saved as user accounts, discounts missing from order lines, stock split across two kinds of rows. The importer sorts that out and is safe to run again.
Checking it38 of 38 stock rows matched. 18 orders and 7 customer accounts came across, and the order total matched Shoper's.
Old linksEvery old URL redirects to its new page, images included. A self-test checks 132 paths.
Practice runA full dry run on staging showed one payment method failing. It turned out to fail only in the provider's sandbox, which I confirmed with a real 1 zł payment.
The switchAbout 36 minutes, following a written runbook.
What broke quietlyAfter the import, old orders were missing from the sales reports. The import had skipped the lookup tables the reports read from. I found it and resynced them.

Keeping the AI honest

Agents are fast, and sometimes confidently wrong. So nothing goes live on their say-so.

  1. BriefI write a short task file: what to build, which files the agent owns, how to test it.
  2. AgentsEach one works in its own git worktree, so several can run at once without stepping on each other.
  3. ProofEach agent hands back a written report and screenshots.
  4. ReviewA second agent reviews the diff. Then it's a small pull request, and I approve the merge.
  5. DeployBackup first, then one script. Nothing goes to production without my OK.
  6. CheckTest scripts replay the real flows: consent, tracking, checkout, redirects.

It still went wrong a few times. Here's what happened and what I changed.

One agent's merge overwrote another's fileNow every agent has a list of files it owns, and only those get merged.
A command said "success" and changed nothing. An API said "no errors" while a job was stuck.I don't trust success messages or empty error lists. Every change gets read back or checked on the real page.
An agent made a test ad campaign in the wrong accountIt was still paused, so I deleted it. Since then, anything that spends money needs my OK.

I also have an assistant on my phone, through Discord, for questions like "did that order go through?". It can look but it can't change anything, and that isn't left to the model.

ServerIts SSH key can only run three read commands. Everything else is refused and logged.
Shop dataIts shop user is read-only.
AdsAn allowlist lets 57 read tools through and blocks the rest, including any that get added later.
E-mailRead-only, shop mailboxes only, and whatever an e-mail says is treated as untrusted.

Two small ones

Shipping labels print themselves

The courier sends an A4 PDF with the label in one corner. My printer takes 100 × 150 mm stickers. About 100 lines of shell now crop and print each label the moment I download it. At first the labels came out with blank bands. The agent worked out that the printer was dropping data, and a 30-line driver patch fixed it.

An iPhone bug that stays fixed

The price filter didn't work on iPhone. A Playwright script reproduces it in WebKit, Chromium and Firefox. Three causes, all fixed: from 6 and 8 of 20 checks passing to 20 of 20. The script stays in the repo so the bug can't sneak back.

One VPS that I set up and look after myself. It hosts the shop, the listmonk newsletter, n8n, and game servers for my friends and me. Backups run every night, encrypted and off-site, and I get an alert if one goes missing.
